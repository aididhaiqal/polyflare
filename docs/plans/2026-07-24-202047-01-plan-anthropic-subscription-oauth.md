# Native Anthropic subscription-OAuth accounts

**Goal:** Let PolyFlare onboard, refresh, select, and safely use operator-owned Anthropic subscription-OAuth accounts for the native `/v1/messages` path through a versioned Claude Code-compatible client profile.

**Why planning is required:** This changes an authenticated outbound boundary, persists refreshable credentials, and changes the public Anthropic Messages behavior across account pools.

**Acceptance:** An operator can complete an account-owner-authorized PKCE login for an Anthropic account, assign it to a pool, and use that account for a real Claude Code client's native Messages requests through a versioned compatibility profile. The initial OAuth contract and synthetic-request profile are grounded in the supplied source plus a content-safe loopback capture of installed Claude Code `2.1.218` / Anthropic SDK `0.94.0`: current production OAuth endpoints, public client registration, `/v1/messages?beta=true`, OAuth/model beta composition, Claude CLI and Stainless headers, and session/request-ID behavior. For a validated real-Claude request, PolyFlare strips caller authorization but preserves an explicit allowlist of the client's current protocol envelope, native body, tool names, and SSE semantics; it does not replace current client evidence with older hardcoded values. Server-generated traffic uses a separately versioned captured profile. Tokens refresh five minutes before expiry or once after a pre-output 401, with one single-flight, same-account retry; rotated credentials persist before reuse. A release-monitor job discovers new npm `stable` and `latest` versions, captures and diffs them without real credentials or non-loopback traffic, and opens a review artifact without automatically promoting compatibility. Existing Codex OAuth accounts and non-OAuth Anthropic credentials retain their current behavior. Tokens, authorization codes, and request content never reach logs, dashboard APIs, metrics, errors, captures, or debug output. A provider requirement for native attestation, an unrecognized client body, or an incompatible live capture fails closed rather than being hidden with guessed fingerprint fields.

### Outcome 1: Provider-neutral account identity and auth mode

- Work: Add a forward-only store migration that introduces a provider-scoped upstream identity, an explicit upstream-auth mode, a non-secret access-token expiry timestamp, the versioned OAuth-contract profile, and persisted granted scopes. Keep the account's OAuth contract separate from the per-request Claude wire profile so a new Claude release does not rewrite account rows. Backfill existing Codex rows as Codex OAuth without repurposing `chatgpt_account_id`, and keep an API-key/static-bearer mode for existing Anthropic rows. Update `polyflare-store` account models, all account queries/upserts, encrypted-token cache invalidation, and dashboard/read projections so `(provider, upstream_identity)` identifies a re-login target without exposing the identity as a token.
- Risks/open questions: Migration must preserve every existing account row and its encrypted token blobs. Before creating the provider-scoped unique index, detect duplicate non-null Codex identities and stop with a diagnostic or leave the conflicted neutral identity unset for operator resolution; do not silently merge/delete accounts or let index creation wedge startup. The new unique constraint permits legacy rows with no upstream identity; no destructive data rewrite or blanket reauthentication is allowed.
- Verify: new `polyflare-store` migration/repository tests seeded with Codex, legacy Anthropic, Anthropic-OAuth, and duplicate-identity rows; `cargo test -p polyflare-store`.

### Outcome 2: Versioned Claude Code-compatible OAuth onboarding

- Work: Add `polyflare-anthropic` OAuth primitives for authorization-code + PKCE, dynamic loopback callback, hosted manual callback, token exchange, refresh-token rotation, expiry calculation, granted-scope persistence, and typed non-secret identity extraction. Make the first production OAuth-contract profile use the supplied-source/current-client values: public client ID, `https://claude.com/cai/oauth/authorize`, `https://platform.claude.com/v1/oauth/token`, `https://platform.claude.com/oauth/code/callback`, and OAuth beta. Keep these values in one reviewed module with source/capture provenance, separate from Messages wire profiles, so upstream OAuth and wire changes can be reviewed independently rather than changed as scattered literals. Request `user:inference` by default; request `user:profile` only when profile-derived identity is required, and tolerate profile failure by using the token response's account UUID/email. Extend `polyflare accounts login` with a provider selector that defaults to Codex for compatibility and supports `--provider anthropic --pool <slug>`. On successful Anthropic login, upsert by the new provider-scoped identity, encrypt access/refresh tokens with the existing `TokenCipher`, persist the raw expiry and granted scopes separately, and print only the redacted account identity.
- Risks/open questions: Do not request unrelated Claude Code permissions (MCP, file upload, API-key creation, or sessions) unless the operator explicitly authorizes that scope expansion, and never expand scopes during refresh beyond the persisted grant. Production endpoint selection is allowlisted to the captured Anthropic endpoints; test endpoint injection is limited to unit/integration constructors and is never a production environment override, preventing OAuth endpoint mix-up or token exfiltration. Both loopback and pasted `code#state` flows validate the original state locally; the automatic redirect uses an OS-assigned localhost port while the manual flow uses the hosted callback URI. This supports an operator-owned OAuth session only; it does not import another client’s credentials or bypass the provider’s account authorization.
- Verify: mocked PKCE callback/exchange/refresh tests in `polyflare-anthropic`; CLI/onboarding integration tests for insert, idempotent re-auth, pool assignment, state mismatch, callback timeout, and token redaction.

### Outcome 3: Claude Code-native Messages egress profile

- Work: Carry the selected account's explicit auth mode/OAuth contract and a typed, content-free inbound Claude envelope into `polyflare_core::Account`/`PreparedRequest`. Detect the dialect at ingress by validating the Claude session/request UUIDs, parsing beta tokens, recognizing the Claude CLI user agent, and confirming the already-native request carries the captured attribution and Agent SDK identity blocks. For an admitted real-Claude request, preserve the validated path/query and an explicit outbound allowlist (`accept`, `content-type`, `anthropic-version`, ordered `anthropic-beta`, Claude CLI `user-agent`, `x-app`, direct-browser flag, `x-stainless-*`, Claude session/request IDs, and any captured opaque native-attestation field), then replace authorization with the selected account's Bearer. Never forward caller authorization, cookies, host/content-length/hop-by-hop fields, or arbitrary `x-*` headers. Preserve an attestation value only as opaque client input: never generate, decode, log, or claim it remains valid after account substitution. Preserve the native body, tool names, and SSE bytes; do not duplicate Claude attribution/identity blocks, prefix tools, synthesize a token-derived session UUID, or add compatibility fields absent from the admitted request.
- Work: Put server-generated Messages traffic behind a separate `ClaudeWireProfileRegistry`; its initial reviewed fixture is Claude Code `2.1.218` / SDK `0.94.0` and may synthesize only the exact content-free fields proven by capture. It is never selected merely because an inbound client claims a newer version. Retain the current static-bearer behavior for legacy accounts.
- Risks/open questions: This is application-protocol fidelity, not byte-level client impersonation: PolyFlare's HTTP stack still changes header serialization, connection behavior, HTTP/TLS fingerprint, and possibly native attestation. Better CCFlare follows the useful pass-through shape but likewise uses ordinary `fetch` and does not solve transport identity or attestation. The dummy-token/custom-base capture proves request shape but not first-party-only fields or server acceptance. Current Claude source has an optional native `cch` attestation inserted below JavaScript; if Anthropic binds or requires it, account substitution or synthetic traffic may fail and release is blocked. A generic Anthropic SDK body that lacks the Claude identity markers is not eligible for raw subscription-OAuth forwarding; the Agent SDK bridge decision gate below is a distinct runtime path, not permission to disguise arbitrary HTTP as Claude Code.
- Verify: deterministic ingress/executor tests asserting dialect admission, header allowlisting and credential replacement, exact path/query preservation, beta order/deduplication, validated inbound session continuity (never token-derived), opaque-attestation handling, OAuth-versus-static behavior, and byte-identical body/tool/SSE fixtures captured from Claude Code `2.1.218`; profile-registry tests separately assert synthetic headers and reject unknown/unpromoted versions; existing `executor_stream` tests remain green; `cargo test -p polyflare-anthropic` and `cargo test -p polyflare-server --test messages_ingress`.

### Outcome 4: Non-native Claude Agent SDK bridge decision gate

- Work: Retain the isolated `poc/claude-agent-sdk-bridge` experiment as the proof harness for translating one non-streaming OpenAI-style system/user turn into `@anthropic-ai/claude-agent-sdk`, executing it through an explicitly selected Claude Code `2.1.218` binary with dummy OAuth and a loopback fake Anthropic server, and translating the SDK result back to OpenAI shape. Keep dependencies and generated files outside the Rust workspace. The POC must disable tools, persistence, filesystem settings, telemetry, updater/error-reporting traffic, and real credentials; require an explicit loopback upstream; use fresh temporary config/workspace directories; redact authorization; and retain only header names, safe protocol values, and hashes/lengths of text in the capture.
- Work: Treat production adoption as a separate architecture decision. If approved after the POC and live gate, define a bounded sidecar protocol and isolated per-account Agent SDK workers; map each PolyFlare conversation to one SDK session; enforce process/resource/cancellation limits; and keep OAuth credentials, config directories, and session state from crossing account boundaries. Multi-turn history uses SDK resume rather than replaying arbitrary assistant history. External OpenAI tool calling requires a separately tested MCP suspension/resume bridge before it is enabled.
- Risks/open questions: The POC proves that the official runtime constructs the request, but not raw Messages equivalence or subscription-account acceptance. Its captured external identity is intentionally truthful (`sdk-ts`, Agent SDK version, and PolyFlare client-app), and the runtime injects Claude/Agent SDK system blocks plus a dynamic user-context block even with tools and filesystem setting sources disabled. Those semantic additions mean this cannot silently replace stateless Chat Completions. A custom-base capture still cannot prove first-party-only request IDs or `cch` attestation. The current dependency graph also carries a moderate Windows-only `@hono/node-server` path-traversal advisory through the MCP SDK; the local loopback POC does not invoke static serving, but production adoption is blocked until the dependency is upgraded or the affected surface is removed.
- Verify: `cd poc/claude-agent-sdk-bridge && npm_config_cache=/private/tmp/polyflare-npm-cache npm ci --ignore-scripts --omit=optional && CLAUDE_EXECUTABLE=/absolute/path/to/claude npm test && CLAUDE_EXECUTABLE=/absolute/path/to/claude npm run poc`; assert the capture shows Claude Code `2.1.218`, Agent SDK `0.3.218`, Anthropic SDK `0.94.0`, the declared `x-client-app`, OAuth beta, `/v1/messages?beta=true`, redacted Bearer auth, no tools, hashed text only, and a translated completion.

### Outcome 5: Provider-dispatched, single-flight reactive refresh

- Work: Generalize the existing Codex-only refresh seam so it dispatches from the selected account's provider/auth mode. Refresh Anthropic OAuth credentials five minutes before the stored raw expiry and after a pre-output 401; reuse `RefreshLocks` and the rejected-token comparison to ensure one Anthropic refresh per account. Send only the persisted granted scopes on refresh. Persist the new access token, raw expiry, and replacement refresh token (or retain the old refresh token if the response omits one) before retrying once on the same account. Classify permanent OAuth failures as `reauth_required`, preserve transient failures without corrupting tokens, and only retry before client-visible stream bytes.
- Risks/open questions: Never refresh a static-bearer/API-key account, retry on a different account under the guise of token refresh, or use the Codex auth server for an Anthropic account. A persistence failure after rotation must fail closed rather than use a token that cannot be recovered after restart.
- Verify: server tests with a mock Anthropic token endpoint for concurrent 401s, peer-refresh adoption, permanent failure, transient failure, persistence failure, and a native `/v1/messages` same-account retry; `cargo test -p polyflare-server --test messages_ingress` plus focused reactive-auth tests.

### Outcome 7: Current Claude compatibility intelligence

- Work: Add a content-safe compatibility probe under `scripts/compat/anthropic/` and reviewed fixtures under `crates/polyflare-anthropic/tests/fixtures/claude-code/<version>/`. A scheduled/manual CI job queries the official npm registry for both `stable` and `latest`, records version, publish timestamp, tarball integrity, and platform package, and downloads exact packages with lifecycle scripts disabled. It obtains the matching official platform binary directly from the package's declared optional dependency, verifies registry integrity, and runs `claude --version` plus a dummy-token Messages probe in a fresh temporary config with telemetry/nonessential traffic disabled, a loopback-only capture server, bounded timeouts, and external egress denied during execution. Normalize away authorization, content, random IDs, dates, machine paths, architecture/runtime values, and header order unless ordering is semantically relevant; retain method/path/query, header names and safe values, beta order, body field/type shape, system-block hashes/roles, tool names/schema hashes, SDK version, and SSE framing. Run static string checks for authorize/token/profile/callback endpoints, scope names, beta identifiers, and native-attestation hooks separately because a Messages capture cannot prove the OAuth contract. Compare the normalized result with the newest promoted profile and publish a machine-readable diff plus human review summary; never commit downloaded binaries or raw captures.
- Work: Add a passive, content-free observation path for admitted real Claude requests that records only seen Claude version, SDK/Stainless version, safe beta names, envelope-shape hash, first/last seen time, and compatibility disposition. This borrows Better CCFlare's useful ingress-version observation but persists bounded metadata and never promotes from a user-agent alone. A newer observed version schedules or requests the isolated probe; it does not alter live synthetic headers.
- Risks/open questions: npm `latest` can lead `stable`, and Better CCFlare `v3.5.42` demonstrates why a single hardcoded CLI version is insufficient: it pins `2.1.217`, learns only the inbound UA in memory, and its synthetic probe still pins SDK `0.60.0` plus a small beta set. Registry discovery is therefore informational until capture, tests, and an authorized live gate pass. Do not run npm lifecycle scripts, use a real OAuth token, send prompt content outside loopback, auto-open a compatibility PR containing raw client data, or auto-promote a new profile. If the official package layout, probe behavior, endpoints, attestation, or body shape changes unexpectedly, mark the candidate `blocked` and retain the last reviewed profile.
- Verify: fixture-based normalization/redaction/diff tests; a hermetic fake-registry job proving `stable`/`latest` discovery, integrity failure, package-layout change, external-egress denial, timeout, and no-secret capture; manual execution against exact `2.1.218` reproduces the reviewed fixture without contacting Anthropic.

### Outcome 8: Compatibility gate and release verification

- Work: Promote a compatibility candidate only by a reviewed source/registry/capture diff, deterministic tests, and then—with explicit operator authority and an operator-owned Anthropic account—a content-free first-party acceptance comparison. Run a smoke test covering initial login, native streaming and non-streaming Messages, tool round-trip, token expiry/401 refresh, account-pool selection, pass-through versus synthetic profile selection, and re-auth-required behavior. Keep captures content-free and revoke/test only the target account if the provider supports revocation. A mismatch, native-attestation requirement, or provider rejection blocks release; it is not papered over with arbitrary extra headers, copied credentials, detection-evasion changes, or suppressed errors.
- Verify: `cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && git diff --check && cargo build --release -p polyflare-server`, followed by the authorized loopback smoke test.
